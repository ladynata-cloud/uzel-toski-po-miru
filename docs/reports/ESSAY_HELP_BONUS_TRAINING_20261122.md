# Результат ограниченного обучения выбора помощи

## Решение

**REJECT — экспериментальный кандидат не заменяет действующий классификатор.**
На заранее отделённых 100 учебных обращениях верных назначений стало 64
вместо 62: прирост 2 при требовании не менее 10. На 20 посторонних обращениях
число ненужных учебных подсказок выросло с 1 до 2. Эти два нарушения достаточны
для отказа независимо от способа подсчёта precision.

Кандидат сохранён только в
`essay_workshop/assistant/experiments/bonus-2026-11-22/candidate-model.js`.
Canonical `essay_workshop/intent-model.js` и `assistant/intent-training.json`
не менялись. Сайт и автономный тренажёр продолжают использовать прежнюю модель.
Коммитов, push, merge и публикации в рамках этой проверки не было.

Машиночитаемые агрегаты, хэши, учёт стоимости и результаты дополнительных
проверок: [ESSAY_HELP_BONUS_TRAINING_20261122.metrics.json](ESSAY_HELP_BONUS_TRAINING_20261122.metrics.json).

## Что именно обучалось

Это существующая локальная многоклассовая логистическая регрессия. Она выбирает
один из пяти видов помощи по короткой просьбе ученика: тезис, эпизод,
объяснение связи, формулировка или возражение. Шестой класс `other` и прежний
порог позволяют отказаться от учебного назначения. Модель не генерирует
разбор сочинения и не проверяет литературные факты. Её показатель уверенности
не является откалиброванной вероятностью правильного ответа.

OpenAI использовался как источник синтетических примеров и второй проход
проверки меток. Это не fine-tuning генеративной OpenAI-модели и не обучение
с подкреплением. Обновление весов выполнялось локально на CPU, с прежними
2100 признаками, seed, порогом и 18 эпохами.

Получены 252 синтетических обращения: первоначальные 192 и дополнение 60,
зафиксированное до обучения и открытия контроля. Модель проверки меток
приняла **все 252**, поэтому её согласие само по себе не подтверждает качество
разметки. Отдельный семантический просмотр ассистентом исключил 28
неоднозначных или дефектных формулировок. Приняты 224 новых примера;
вместе с 372 прежними получилось **596**. Новые примеры распределены так:

| Метка | Принято новых |
|---|---:|
| `thesis` | 27 |
| `scene` | 42 |
| `explain` | 41 |
| `wording` | 36 |
| `counter` | 37 |
| `other` | 41 |

Ученические работы, данные преподавателей и их личные сведения в генерацию
и обучение не передавались. Человеческой преподавательской проверки этих
примеров не было. Формальная оценка, воспроизводимость и тесты выполнялись
локально, без live API и без данных реальных учеников.

| Условие на sealed120 | Baseline | Candidate | Результат |
|---|---:|---:|---|

| Число неверных учебных назначений не растёт | 7 | 7 | PASS |
| Не более 1 ненужной подсказки на 20 посторонних | 1 | 2 | FAIL |

До формального запуска precision был определён консервативно: число верных
учебных назначений делится на все выданные учебные назначения, включая
неверные назначения и срабатывания на `other`. Для кандидата это
64 / (64 + 7 + 2). Если исключить посторонние обращения из знаменателя,
получается relevant-only precision 90,14% против 89,86% у baseline.
Обе величины сохранены; решение REJECT не зависит от этой разницы.

## Полное сравнение наборов

В тройке чисел указаны **верно / неверно / отказ** на учебных обращениях.
Отказ означает отсутствие уверенного назначения; он не считается верным
учебным ответом. Для `other` приведено число ненужных подсказок.

| Набор | Учебных / other | Baseline | Candidate | Other: база → кандидат |
|---|---:|---:|---:|---:|
| Новый dev | 60 / 12 | 41 / 1 / 18 | 39 / 1 / 20 | 3 → 2 |
| Новый sealed | 100 / 20 | 62 / 7 / 31 | 64 / 7 / 29 | 1 → 2 |
| `intent-evaluation.json` | 30 / 6 | 28 / 0 / 2 | 27 / 0 / 3 | 0 → 0 |
| `intent-exam-2026-11-20.json` | 40 / 8 | 24 / 2 / 14 | 24 / 3 / 13 | 1 → 1 |
| `intent-exam-2026-11-21.json` | 30 / 6 | 21 / 0 / 9 | 21 / 1 / 8 | 1 → 1 |
| Исторический `intent-blind-2026-11-21.json` | 20 / 4 | 10 / 0 / 10 | 9 / 0 / 11 | 1 → 2 |

Исторический набор с `blind` в имени уже использовался раньше; он не выдаётся
за новый независимый контроль. Дополнительные наборы также не показывают
устойчивого улучшения. Причина недостаточного качества этим опытом отдельно
не установлена; результаты не дают основания просто нарастить расходы или
подбирать параметры по использованному sealed-набору.

## Отдельные проверки после решения

**Воспроизводимость — PASS.** Один детерминированный расчёт в памяти из
неизменных training596, seed и runtime дал точный SHA256 замороженной модели.
Python 3.12.14, Node v24.22.3; 2100 признаков, 18 эпох, около 0,59 секунды.
Новый файл модели не записывался и новый кандидат не выбирался.

**Coach / feedback — 16/16 PASS для каждой модели.** Существующие
`tests/essay-workshop-worldview.test.cjs` и
`tests/essay-answer-feedback.test.cjs` выполнены в отдельных временных копиях
с настоящим baseline и с точной копией кандидата. Тесты и их assertions
не менялись. Canonical файлы при подстановке кандидата не трогались.

Наблюдение показало предел этой проверки: из 74 вызовов наставника лишь 4
дошли до `EssayIntent.classify`, и только один в каждом варианте вернул
готовое действие `intentFeedback`. Baseline назначил `explain`, кандидат —
`scene`; по три остальных результата были `null`. Существующие assertions
допускают это различие. Пять учебных действий полностью не покрыты.
`answer-feedback` вообще не использует intent-модель. Поэтому PASS означает
совместимость и сохранение проверенных ограничений, а не улучшение помощи
к абзацу. Старые `turn-cases.json` описывают контракт другого, генеративного
помощника и не засчитываются как исполненные тесты этого классификатора.

**Бюджетный runner — 7/7 PASS.** Все обращения замокированы, используются
выдуманные ключи во временных файлах. Проверены фиксированный endpoint,
`store: false`, запрет перенаправлений, слово JSON во входе, запись резерва
до отправки, отказ при превышении лимита, сохранение неопределённого резерва,
запрет повтора, чтение завершённого cache без сети и ключа, отсутствие секрета
в сообщении ошибки и блокировка при стоимости выше резерва.

Полная сборка сайта, автономного комплекта и браузерный прогон здесь не
запускались: модель отклонена, runtime и используемые сборкой источники
побайтово совпадают с base. `exam_tracks.py` читает canonical
`intent-model.js`; experimental path не подключён. Существующий CI workflow
не изменён и сохраняет свои обычные проверки при открытии PR.
