# Узел тоски по миру

Литературная мастерская: русская литература, православная мысль и самостоятельное письмо.

Основной адрес для сборки по умолчанию — **https://ladynata-cloud.github.io/uzel-toski-po-miru/**.
В проекте 545 готовых HTML-страниц и исходники для их пересборки. Для работы сайта ChatGPT, OpenAI API и учётная запись ChatGPT не нужны. Сайт можно перенести на любой хостинг статических файлов. Ссылки на внешние тексты и музыкальные записи по-прежнему зависят от соответствующих сайтов.

## Что где лежит

- `dist/` — весь готовый сайт: HTML, оформление, скрипты, изображения и карта сайта. Файл `CNAME` создаётся только для сборки с собственным доменом.
- `build.py` — сборка страниц.
- `site_config.py` — адрес публикации из переменной окружения `SITE_URL` и поддержка пути проекта на GitHub Pages.
- Файлы `.py` и `.json` в корне — тексты и данные, из которых собирается сайт.
- `verify_site.py` — проверка страниц, ссылок, изображений и структуры.
- `.github/workflows/pages.yml` — автоматическая сборка, проверка и публикация при обновлении ветки `main`.
- `SOURCE_NOTES.md` — описание состава материалов и история подготовки. Старое указание о закрытом доступе относится к прежней публикации в ChatGPT Sites; текущая копия подготовлена по запросу автора для GitHub Pages.

## Переход на адрес github.io

1. Сначала добавить обновлённые исходники и workflow в ветку `main` репозитория `ladynata-cloud/uzel-toski-po-miru`. В **Settings → Pages → Build and deployment → Source** должен быть выбран **GitHub Actions**.
2. Дождаться успешной сборки. Workflow сначала читает текущий адрес из настроек Pages, затем подставляет его в `SITE_URL`. Пока в настройках указан собственный домен, сайт продолжает собираться для него.
3. В **Settings → Pages → Custom domain** удалить `usel-toski-po-miru.art` кнопкой **Remove**. Это отключает привязку домена к GitHub Pages; сам домен у регистратора не удаляется.
4. Во вкладке **Actions → Publish literature site → Run workflow** запустить публикацию для `main`. Новая сборка автоматически использует `https://ladynata-cloud.github.io/uzel-toski-po-miru/`: этот путь учитывается в навигации, изображениях, скриптах, метаданных, карте сайта и скачиваемом списке материалов.
5. После успешного завершения открыть адрес `https://ladynata-cloud.github.io/uzel-toski-po-miru/` и проверить переход в выбранный класс и занятие. HTTPS для адреса GitHub не требует настройки DNS в REG.RU.

Удаление файла `dist/CNAME` само по себе не меняет настройки Pages при публикации через GitHub Actions. Пока собственный домен сохранён в **Settings → Pages**, GitHub может перенаправлять адрес `github.io` на него. Обновление исходников и переключение адреса — отдельные действия.

Карта сайта для этого адреса: `https://ladynata-cloud.github.io/uzel-toski-po-miru/sitemap.xml`. При настройке поиска её нужно указать напрямую в инструментах вебмастера. `robots.txt` внутри папки проекта не управляет всем доменом `ladynata-cloud.github.io`: поисковики читают этот файл только в корне домена.

## Возврат к собственному домену при необходимости

В **Settings → Pages → Custom domain** указать `usel-toski-po-miru.art`, настроить DNS по таблице ниже и снова запустить workflow. Он использует адрес из настроек GitHub; вручную менять исходники не нужно. После проверки DNS и выпуска сертификата включить **Enforce HTTPS**. Для сборки под собственный домен автоматически создаётся соответствующий `CNAME`.

## DNS в Рег.ру

Использовать DNS-серверы `ns1.reg.ru` и `ns2.reg.ru`, если зона обслуживается в Рег.ру. В разделе ресурсных записей нужны следующие значения:

| Тип | Поддомен | Значение |
| --- | --- | --- |
| A | @ | 185.199.108.153 |
| A | @ | 185.199.109.153 |
| A | @ | 185.199.110.153 |
| A | @ | 185.199.111.153 |
| CNAME | www | ladynata-cloud.github.io. |

Таблица соответствует GitHub Pages. Старые A/AAAA/CNAME для этих же имён могут конфликтовать: сначала проверить существующие записи. MX/TXT для почты и проверки владения не удалять. Не создавать перенаправление на старый адрес ChatGPT Sites и не применять записи подключения ChatGPT Sites.

## Как обновлять самостоятельно

Для сборки нужен Python 3.9 или новее, сторонние пакеты не требуются:

```sh
python3 build.py
python3 verify_site.py
```

Готовые файлы появятся в `dist/`. Эти команды используют адрес `github.io` и путь проекта. Для проверки локально в корне тестового сервера временно собрать с другим адресом:

```sh
SITE_URL=http://localhost:8000 python3 build.py
SITE_URL=http://localhost:8000 python3 verify_site.py
python3 -m http.server 8000 --directory dist
```

Открыть `http://localhost:8000`. Не открывать HTML двойным щелчком: навигация использует пути от корня адреса публикации. После локальной проверки `python3 build.py` снова подготовит `dist/` для `github.io`.

После изменений исходников отправить их в `main`: настроенный GitHub Actions пересоберёт и опубликует сайт по текущему адресу из настроек Pages. Для ручной сборки на другом хостинге передать одинаковый `SITE_URL` командам сборки и проверки, например:

```sh
SITE_URL=https://usel-toski-po-miru.art python3 build.py
SITE_URL=https://usel-toski-po-miru.art python3 verify_site.py
```

## Резервная копия и перенос

Хранить скачанный архив на своём компьютере и, при желании, на внешнем носителе. Для другого статического хостинга сначала собрать сайт с его `SITE_URL`, затем загрузить **содержимое `dist/` в каталог, соответствующий адресу публикации**. Исходники в остальных файлах нужны для дальнейшего редактирования и пересборки.

Никаких паролей и ключей доступа этот архив не содержит. Ученические черновики на сервер не отправляются; их скачивание работает в браузере.

Видимый текст всех 545 страниц и 36 файлов изображений, оформления и скриптов совпадает с исходной версией.
