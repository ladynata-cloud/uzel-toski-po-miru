# Узел тоски по миру

Литературная мастерская: русская литература, православная мысль и самостоятельное письмо.

Подготовлено для домена **usel-toski-po-miru.art** и GitHub Pages.
В архиве 544 готовые HTML-страницы и исходники для их пересборки. Для работы сайта ChatGPT, OpenAI API и учётная запись ChatGPT не нужны. Сайт можно перенести на любой хостинг статических файлов. Ссылки на внешние тексты и музыкальные записи по-прежнему зависят от соответствующих сайтов.

## Что где лежит

- `dist/` — весь готовый сайт: HTML, оформление, скрипты, изображения, карта сайта и файл домена.
- `build.py` — сборка страниц и настройка основного адреса (`ORIGIN`).
- Файлы `.py` и `.json` в корне — тексты и данные, из которых собирается сайт.
- `verify_site.py` — проверка страниц, ссылок, изображений и структуры.
- `.github/workflows/pages.yml` — автоматическая сборка, проверка и публикация при обновлении ветки `main`.
- `SOURCE_NOTES.md` — описание состава материалов и история подготовки. Старое указание о закрытом доступе относится к прежней публикации в ChatGPT Sites; текущая копия подготовлена по запросу автора для GitHub Pages.

## Первичная публикация

1. В GitHub под аккаунтом `ladynata-cloud` создать репозиторий `uzel-toski-po-miru`. Для бесплатного GitHub Pages выбрать **Public**. Исходники такого репозитория будут общедоступны.
2. Поместить в ветку `main` содержимое этой папки, включая `.github/workflows/pages.yml`. Сам ZIP вместо файлов загружать не нужно.
3. В **Settings → Pages → Build and deployment → Source** выбрать **GitHub Actions**.
4. В **Custom domain** указать `usel-toski-po-miru.art` и сохранить. В режиме GitHub Actions одного файла CNAME недостаточно — адрес нужно задать в Settings.
5. После задания адреса в GitHub настроить DNS у регистратора по таблице ниже. Желательно также подтвердить домен в настройках профиля GitHub → Pages: индивидуальную TXT-запись выдаёт GitHub.
6. Во вкладке **Actions** выбрать **Publish literature site → Run workflow**, если публикация ещё не запустилась. Дождаться успешного выполнения.
7. После проверки DNS и выпуска сертификата в **Settings → Pages** включить **Enforce HTTPS**.

Репозиторий и настройки Pages на момент подготовки этого архива ещё не созданы. Архив не означает, что сайт уже опубликован на GitHub.

## DNS в Рег.ру

Использовать DNS-серверы `ns1.reg.ru` и `ns2.reg.ru`, если зона обслуживается в Рег.ру. В разделе ресурсных записей нужны следующие значения:

| Тип | Поддомен | Значение |
| --- | --- | --- |
| A | @ | 185.199.108.153 |
| A | @ | 185.199.109.153 |
| A | @ | 185.199.110.153 |
| A | @ | 185.199.111.153 |
| CNAME | www | ladynata-cloud.github.io. |

Таблица соответствует GitHub Pages. Старые A/AAAA/CNAME для этих же имён могут конфликтовать: сначала проверить существующие записи. MX/TXT для почты и проверки владения не удалять. Не создавать перенаправление на старый адрес ChatGPT Sites и не применять записи подключения ChatGPT Sites.

## Как обновлять самостоятельно

Для сборки нужен Python 3.9 или новее, сторонние пакеты не требуются:

```sh
python3 build.py
python3 verify_site.py
```

Готовые файлы появятся в `dist/`. Проверить локально:

```sh
python3 -m http.server 8000 --directory dist
```

Открыть `http://localhost:8000`. Не открывать HTML двойным щелчком: навигация использует пути от корня сайта.

После изменений исходников отправить их в `main`: настроенный GitHub Actions пересоберёт и опубликует сайт. Для смены адреса изменить `ORIGIN` и строку записи `CNAME` в `build.py`, пересобрать сайт, затем обновить настройки хостинга и DNS.

## Резервная копия и перенос

Хранить скачанный архив на своём компьютере и, при желании, на внешнем носителе. Для другого статического хостинга загрузить **содержимое `dist/` в корень сайта**. Исходники в остальных файлах нужны для дальнейшего редактирования и пересборки.

Никаких паролей и ключей доступа этот архив не содержит. Ученические черновики на сервер не отправляются; их скачивание работает в браузере.

Изображения и остальные ресурсы сохранены без изменений. Проверка отображения в браузере, воспроизведения внешней музыки и реального запуска GitHub Actions в эту проверку не входит.
